# Phase 4E TestFlight Readiness and Device QA

Phase 4E prepares the native iOS app for simulator and real-device QA. It does not claim TestFlight readiness.

## Current baseline
- Base commit: `8371c32cf5b91f34702f65fa7b0a61cb47d77df7` on `main`.
- Phase 4B, Phase 4C, and Phase 4D are merged into `main`.
- Guest mode remains the primary native path.
- Native Sign in with Apple is scaffold-only and disabled.
- Premium/subscriptions are not implemented.
- No telemetry or crash-reporting SDK is bundled.

## iOS project configuration audit
- App display name: `Calorie Compass`.
- Bundle identifier: `com.caloriecompass.ios`; still a placeholder until the App Store Connect record is final.
- Version/build: `MARKETING_VERSION = 1.0`, `CURRENT_PROJECT_VERSION = 1`.
- Deployment target: iOS `17.0`.
- Device family: iPhone and iPad (`TARGETED_DEVICE_FAMILY = "1,2"`).
- Info.plist: generated by Xcode build settings; launch screen generation is enabled.
- Base URL: non-secret `CALORIE_COMPASS_BASE_URL` is set to `https://calorie-compass-chi.vercel.app` and may be overridden by scheme environment for simulator QA.
- Signing: automatic signing is enabled, but no Apple Developer Team is committed.
- Assets: `AppIcon` slots exist but remain placeholders with no image filenames assigned.
- Scheme: shared `CalorieCompass` scheme supports build, test, profile, analyze, and archive actions.

## Simulator QA checklist
- Build and run the shared `CalorieCompass` scheme on a current iPhone simulator.
- Repeat on a small simulator, such as iPhone SE, if available.
- Confirm launch screen, tab bar, Today, Log, History, and Profile render without clipping.
- Exercise loading, empty, error, retry, offline, and session-expired states.
- Log a meal, review detected items, save it, then confirm Today and History refresh.
- Edit and delete a saved meal only after confirmation.
- Try invalid meal edits and confirm validation blocks malformed PATCH payloads.
- Confirm the disabled Apple sign-in entry point says coming soon and does not start real auth.
- Test light mode, dark mode, one larger Dynamic Type size, and keyboard dismissal.
- Verify no API keys, provider tokens, or sensitive values are present in the built app bundle.

## Real-device QA checklist
- Build and run on at least one physical iPhone with the intended signing team.
- Test Wi-Fi and cellular or hotspot networking against production backend.
- Confirm slow network and offline states do not block navigation or fake success.
- Confirm keyboard, safe areas, sheets, alerts, and destructive confirmations feel usable by touch.
- Confirm VoiceOver can reach tab items, retry buttons, meal rows, remove buttons, save buttons, and delete confirmations.
- Capture device model, iOS version, build number, tester session state, and any failed steps.

## App Store Connect checklist
- Create or select the final App Store Connect app record.
- Replace placeholder bundle id if needed before upload.
- Set the Apple Developer Team and confirm archive signing.
- Replace all placeholder app icon slots with original Calorie Compass artwork, including the 1024x1024 marketing icon.
- Capture clean screenshots for Today, Log, meal review, History, meal detail, Profile, and one offline/session state.
- Prepare review notes that say native Sign in with Apple is not implemented in this build.
- Upload internal TestFlight builds only after archive succeeds locally on macOS.

## Metadata and privacy checklist
- Complete privacy labels for meal logs, nutrition estimates, profile fields, account/session identifiers, and diagnostics if added later.
- Confirm the privacy policy describes web account export/delete fallbacks while native account tools are unavailable.
- Keep nutrition-disclaimer copy short: estimates are informational, may be approximate, and are not medical advice.
- Do not log or screenshot real private meal logs or profile data without tester approval.
- Do not include OpenAI, database, provider, Apple private key, or API credentials in the iOS app.

## CI and release confidence
- GitHub Actions `iOS CI` runs on `main`, Phase 4E branch pushes, and PRs targeting `main`.
- CI verifies Xcode build/test and uploads `ios-build.log`, `ios-test.log`, and `ios-test-results.xcresult`.
- CI does not replace interactive simulator QA, physical device QA, signing, archive upload, privacy labels, or screenshots.
